# 面向前端面试的 LangChain 学习路径

## 0. 先建立全局地图：LangChain 到底在解决什么问题

**你要学什么**

先理解一个普通 AI 应用大概长这样：

```txt
用户输入
  ↓
Messages / Prompt
  ↓
Model 调用
  ↓
是否需要调用 Tool
  ↓
Tool 结果回传给 Model
  ↓
最终回答
  ↓
前端流式展示 / 保存上下文 / 结构化输出
```

**你要能说出来**

LangChain 不是“大模型”，它是一个帮助开发者组织 LLM 应用的框架。它把模型调用、消息格式、工具调用、Agent 循环、流式输出、记忆、RAG、观测调试这些常见能力封装起来。

**学到什么程度就够**

能画出这张流程图，并能解释为什么前端做 AI 应用时会遇到这些问题：模型切换、流式输出、工具调用、上下文管理、结构化数据返回。

---

## 1. Model：先学模型调用，不要一上来学 Agent

**你要学什么**

学习 LangChain 里的 model 是什么。它本质上是对 OpenAI、Anthropic、Google、Ollama 等模型 API 的统一封装。官方 JS 文档里把模型的核心方法分成 `invoke`、`stream`、`batch`：`invoke` 是一次性返回完整结果，`stream` 是边生成边返回，`batch` 是批量请求。

**你要掌握**

```txt
model.invoke(messages)   // 普通调用
model.stream(messages)   // 流式调用
temperature              // 控制随机性
maxTokens                // 控制输出长度
model provider           // OpenAI / Anthropic / Google / Ollama
```

**面试能怎么说**

> LangChain 的 Model 层主要是统一不同大模型厂商的调用方式。比如我前端项目后面可以从 OpenAI 切到 Gemini 或本地 Ollama，上层 Agent 和 Tool 逻辑不需要大改。

**学到什么程度就够**

能用 JS/TS 调一次模型，输入一句话，拿到回答。不要深挖模型训练、Transformer、微调。

---

## 2. Messages：理解上下文是怎么传给模型的

**你要学什么**

LangChain 里的 messages 是模型上下文的基本单位。官方文档说，messages 表示模型的输入和输出，包含内容和元数据，用来表示一次对话状态。

你需要理解几种常见角色：

```txt
System Message：系统指令，规定 AI 怎么回答
Human Message：用户输入
AI Message：模型回答
Tool Message：工具调用结果
```

**你要掌握**

比如一个 AI 面试助手：

```txt
System: 你是一个前端面试助手，回答要简洁。
Human: 请解释 React diff。
AI: React diff 是……
```

如果有工具调用：

```txt
Human: 查一下今天北京天气
AI: 我要调用 weather_tool
Tool: 北京今天 12℃，晴
AI: 北京今天晴，12℃
```

**面试能怎么说**

> LLM 本身不是天然记得上下文的，每次调用都要把相关 messages 传进去。LangChain 用统一的 Message 对象管理 system、人类输入、AI 回复和工具结果。

**学到什么程度就够**

能解释“上下文不是模型自动记住的，而是每次请求带过去的 messages”。

---

## 3. Prompt / System Prompt：学会控制模型行为

**你要学什么**

前端面试里很可能问你：你怎么让 AI 按指定格式输出？怎么让它不要乱答？

你需要理解 prompt 主要包括：

```txt
角色设定
任务说明
输出格式
约束条件
示例
```

**你要掌握**

例如：

```txt
你是一个前端面试官。
请用 3 点解释问题。
如果不确定，请说“不确定”，不要编造。
输出格式：
1. 核心概念
2. 面试回答
3. 项目落地
```

**面试能怎么说**

> Prompt 不只是用户输入，而是包含 system 指令、上下文、工具说明、输出格式约束的一整套模型上下文。LangChain 可以把这些内容结构化地组织到 messages 或 agent 配置里。

**学到什么程度就够**

能写一个稳定的 system prompt，让模型按固定格式回答。

---

## 4. Tools：这是 Agent 的核心前置知识

**你要学什么**

Tool 是让模型“能做事”的关键。模型本身只能生成文本，不能真正查数据库、调接口、算天气、读文件。Tool 就是把外部能力注册给模型。

LangChain JS 官方文档里，tools 是核心组件之一，可以创建工具、访问上下文、返回字符串或对象，也可以处理工具错误。

**你要掌握**

一个 tool 通常包括：

```txt
name：工具名称
description：告诉模型什么时候用这个工具
schema：工具参数格式
function：真实执行逻辑
```

比如：

```txt
Tool 名称：get_weather
描述：当用户询问某城市天气时使用
参数：city
执行：请求天气 API，返回天气
```

**面试能怎么说**

> Tool calling 的本质是模型决定“我要调用哪个函数以及传什么参数”，真正执行函数的是我们的程序。模型不是直接联网，而是通过我们暴露的工具间接访问外部系统。

**学到什么程度就够**

会写 2 个简单工具就够：

```txt
1. calculator：做简单计算
2. searchMock：模拟搜索知识库
```

不用一开始接真实搜索 API。

---

## 5. Agent：重点学，面试最容易问

**你要学什么**

Agent 可以理解为“模型 + 工具 + 循环控制”。普通模型调用是一次问答，而 Agent 会判断是否需要调用工具，拿到工具结果后再继续推理，直到生成最终回答。

LangChain JS 里可以用 `createAgent` 创建预构建 Agent；官方文档也提到 Agent 里包含 model、tools、system prompt、memory、streaming、middleware 等核心能力。

**你要掌握 Agent 的基本循环**

```txt
用户提问
  ↓
模型判断是否需要工具
  ↓
需要：生成 tool call
  ↓
程序执行 tool
  ↓
tool 结果作为 Tool Message 回传
  ↓
模型基于结果继续回答
  ↓
直到不再调用工具，返回最终答案
```

**面试能怎么说**

> Agent 不是一个神秘概念，本质是一个循环：LLM 负责决策，程序负责执行工具，工具结果再回到 LLM，直到模型认为可以给最终答案。LangChain 的 createAgent 帮我们封装了这个 ReAct 风格的循环。

**学到什么程度就够**

能做一个最小 Agent：

```txt
输入：帮我规划学习 LangChain
工具 1：searchDocs，返回本地模拟资料
工具 2：calculator，计算学习天数
输出：学习计划
```

你不需要深入 multi-agent、human-in-the-loop、复杂状态图。

---

## 6. Streaming：前端一定要学，性价比很高

**你要学什么**

流式输出是前端 AI 产品体验的核心。LangChain 官方说明，streaming 可以把 agent 运行中的实时更新暴露给应用，提升响应体验，避免用户等完整结果出来。

**你要掌握**

前端重点不是底层协议，而是这几个概念：

```txt
非流式：等完整回答生成完再显示
流式：token 或 message chunk 一段段显示
agent streaming：不仅流式显示文本，还可以显示工具调用进度
```

**面试能怎么说**

> 在 AI 应用里，模型延迟比较高，所以前端通常会用 streaming，把模型生成的 token 或 agent 执行进度实时渲染出来。这样用户可以立刻看到反馈，体验会接近 ChatGPT。

**学到什么程度就够**

能在页面上做一个“打字机效果”的 AI 回复。知道后端可以通过 SSE、ReadableStream 或 WebSocket 把流式内容传给前端。

---

## 7. Memory：理解短期记忆即可

**你要学什么**

LangChain 的 memory 分短期记忆和长期记忆。你的面试目标只需要重点学短期记忆。

官方文档说，短期记忆让应用在一个 thread 或 conversation 中记住之前的交互；对话历史是最常见的短期记忆形式，但长对话会受到上下文窗口、成本和效果下降的影响。

**你要掌握**

```txt
短期记忆：当前会话历史，例如这轮聊天之前说过什么
长期记忆：跨会话保存用户偏好、历史信息
上下文裁剪：消息太长时只保留最近 N 条或做摘要
```

**面试能怎么说**

> LLM 不是真的拥有记忆。短期记忆通常是把当前会话的 messages 存起来，每次请求时带上。问题是上下文窗口有限，所以实际项目里要做裁剪、摘要或只保留关键信息。

**学到什么程度就够**

能实现一个简单聊天历史：

```txt
messages.push(userMessage)
messages.push(aiMessage)
下一次请求带上 messages
```

不用深入向量记忆、长期记忆系统。

---

## 8. Structured Output：前端面试很实用

**你要学什么**

前端经常需要模型返回 JSON，而不是一段自然语言。LangChain 支持结构化输出，JS 文档里提到可以用 Zod schema、JSON Schema 等方式定义期望输出，并由 agent 返回结构化结果。

**你要掌握**

比如让模型返回：

```ts
{
  title: string;
  steps: string[];
  difficulty: "easy" | "medium" | "hard";
}
```

**面试能怎么说**

> 前端不希望只拿到一段不可控文本，很多时候要渲染卡片、表格、步骤条，所以会要求模型返回结构化数据。LangChain 可以通过 schema 约束输出，然后前端按字段渲染。

**学到什么程度就够**

能让 AI 返回一个课程计划 JSON，然后前端渲染成列表。

---

## 9. RAG：了解原理，不必深入向量数据库

**你要学什么**

RAG 是面试里非常常见的问题。你需要知道它解决的是：模型不知道私有知识、最新知识、公司内部知识的问题。

基本流程：

```txt
文档切分
  ↓
Embedding 向量化
  ↓
存入向量数据库
  ↓
用户提问也向量化
  ↓
相似度检索相关文档
  ↓
把文档作为上下文交给模型回答
```

LangChain 官方 JS 文档里有构建 RAG agent 的例子：先定义 retrieve 工具，从 vector store 里查相关内容，再把 retrieve 作为工具交给 agent。

**面试能怎么说**

> RAG 的核心不是让模型重新训练，而是在回答前先从知识库检索相关内容，把检索结果塞进上下文，让模型基于这些资料回答。这样可以降低幻觉，也能接入私有知识。

**学到什么程度就够**

会讲清楚流程就行。代码层面可以先做“假 RAG”：

```txt
本地数组里存几段文档
用户问题来了以后做关键词匹配
把匹配结果放进 prompt
让模型回答
```

不必一开始学 Pinecone、Milvus、Chroma、FAISS。

---

## 10. LangGraph：知道它和 LangChain 的关系即可

**你要学什么**

不要现在深入 LangGraph。你只需要知道：LangChain 是更上层、更容易上手的 agent 框架；LangGraph 是更底层的 agent 编排框架，适合复杂、长时间运行、有状态、可恢复、human-in-the-loop 的 agent。官方也说明，LangGraph 关注 durable execution、streaming、human-in-the-loop 等 agent 编排能力；刚开始做 agents 可以先用 LangChain 的预构建 agent。

**面试能怎么说**

> LangChain 更适合快速搭建常见 Agent；LangGraph 更像底层状态机/流程图框架，适合复杂 Agent，比如多步骤、可中断、可恢复、人工审核、多 Agent 协作。

**学到什么程度就够**

知道区别即可，不需要写 LangGraph。

---

## 11. LangSmith：知道它是调试和观测平台

**你要学什么**

LangSmith 用来观察 agent 运行过程：模型输入了什么、调用了哪个工具、工具结果是什么、最终回答怎么生成的。官方文档说，LangChain agents built with `createAgent` 自动支持 LangSmith tracing，用于捕获、调试、评估和监控 LLM 应用行为。

**面试能怎么说**

> Agent 调试比较困难，因为中间可能有多次模型调用和工具调用。LangSmith 可以记录 trace，帮助我们看到每一步输入输出，排查 prompt、工具调用或上下文问题。

**学到什么程度就够**

知道用途即可。面试时能提到“调试 Agent 时可以看 trace”。

# 推荐目录：按你截图风格改成适合面试的版本

## 1. 什么是 LangChain

### 1.1 为什么需要 LangChain
学习模型调用、工具调用、上下文管理、流式输出这些重复问题。

### 1.2 LangChain 到底是什么
它是 LLM 应用开发框架，不是模型本身。

### 1.3 LangChain、LangGraph、LangSmith 的关系
LangChain 快速做 Agent；LangGraph 做复杂状态编排；LangSmith 做调试观测。

### 1.4 前端为什么要学 LangChain
为了理解 AI 应用后端怎么组织，并能和前端 streaming、结构化渲染、聊天 UI 对接。

---

## 2. LangChain 入门

### 2.1 安装和基本项目结构
用 Node.js / TypeScript 即可。

### 2.2 第一次调用模型
学 `invoke`，输入 messages，拿到 AI 回复。

### 2.3 模型参数
知道 `temperature`、`maxTokens`、`model provider`。

### 2.4 面试表达
能说清楚：LangChain 抹平不同模型厂商 API 差异。

---

## 3. Agent 和 Model

### 3.1 Model 是什么
模型只是“生成文本/消息”的能力。

### 3.2 Agent 是什么
Agent 是“模型 + 工具 + 决策循环”。

### 3.3 普通 Chat 和 Agent 的区别
普通 Chat 只回答；Agent 可以判断是否调用工具。

### 3.4 ReAct 思路
Reason + Act：模型先思考要不要行动，再调用工具，再根据结果回答。

### 3.5 面试表达
重点能讲出 Agent 循环。

---

## 4. Messages

### 4.1 System / Human / AI / Tool Message
理解不同消息角色。

### 4.2 为什么上下文要放进 messages
模型不会自动记住历史。

### 4.3 多轮对话怎么实现
保存历史 messages，每轮请求带上。

### 4.4 上下文窗口问题
历史太长要裁剪、摘要或检索。

---

## 5. Streaming：前端重点

### 5.1 为什么需要流式输出
降低等待感，提升 AI 产品体验。

### 5.2 token streaming 和 agent updates
文本可以流式，工具调用过程也可以展示。

### 5.3 前端如何展示
打字机效果、loading 状态、工具调用状态、错误状态。

### 5.4 面试表达
能说出 SSE / WebSocket / ReadableStream 都可以承载流式返回。

---

## 6. Tools：Agent 的手脚

### 6.1 Tool 是什么
外部函数/API/数据库查询能力。

### 6.2 Tool 的组成
name、description、schema、execute function。

### 6.3 模型如何选择工具
模型根据工具描述和用户问题决定是否调用。

### 6.4 工具调用结果怎么回到模型
工具执行结果变成 Tool Message，再交给模型。

### 6.5 实战
写 calculator 和 mockSearch 两个工具。

---

## 7. 让 Agent 输出你想要的结构

### 7.1 为什么要结构化输出
前端需要稳定 JSON 渲染 UI。

### 7.2 用 schema 限制输出
用 Zod 或 JSON Schema。

### 7.3 常见场景
课程计划、表单抽取、候选人评分、商品推荐卡片。

### 7.4 面试表达
能说出“自然语言适合聊天，结构化输出适合前端渲染”。

---

## 8. Memory：让 Agent 有上下文

### 8.1 短期记忆
当前会话内保存 messages。

### 8.2 长期记忆
跨会话保存用户偏好或历史信息，了解即可。

### 8.3 上下文管理
最近 N 条、摘要、RAG 检索。

### 8.4 面试表达
LLM 没有真正记忆，所谓 memory 是应用层保存并重新注入上下文。

---

## 9. 中间件和错误处理，了解即可

### 9.1 Middleware 是什么
在模型调用前后插入逻辑。

### 9.2 可以做什么
重试、日志、工具过滤、上下文裁剪、权限控制。

### 9.3 学习深度
知道有这个概念即可，不需要深入。

---

## 10. MCP：知道概念即可

### 10.1 MCP 是什么
可以理解为让模型/Agent 连接外部工具和数据源的一种协议。

### 10.2 和 Tools 的关系
Tools 是能力；MCP 更像一种标准化接入方式。

### 10.3 学习深度
前端面试只需要知道它是“标准化工具接入协议”，不用实战。

---

## 11. RAG：面试高频

### 11.1 为什么需要 RAG
解决模型不知道私有知识、最新知识的问题。

### 11.2 RAG 基本流程
文档切分、embedding、向量库、检索、拼接上下文、模型回答。

### 11.3 RAG 和微调的区别
RAG 是检索增强，不改变模型参数；微调是训练模型参数。

### 11.4 最小实战
用本地数组模拟知识库，做关键词检索。

### 11.5 面试表达
能讲出“先查资料，再让模型基于资料回答”。

---

## 12. LangSmith：调试 Agent

### 12.1 为什么 Agent 难调试
中间有多次模型调用和工具调用。

### 12.2 Trace 是什么
记录每一步输入、输出、工具调用。

### 12.3 学习深度
知道 LangSmith 用来 debug、evaluate、monitor 即可。

## 13. 最终小项目：前端面试 AI Agent

建议你做这个项目，够面试用了。

### 项目名称

**前端面试助手 Agent**

### 功能

```txt
1. 用户输入一个前端面试问题
2. Agent 判断是否需要查知识库
3. 调用 mockSearch 工具获取相关知识
4. 模型生成结构化回答
5. 前端流式展示
```

### 工具设计

```txt
searchFrontendKnowledge(query)
作用：从本地 mock 文档里搜索 React、Vue、Webpack、JS、CSS 相关知识

calculateStudyPlan(days)
作用：根据剩余天数生成学习安排
```

### 输出结构

```ts
{
  question: string;
  coreConcept: string;
  interviewAnswer: string;
  projectExample: string;
  followUpQuestions: string[];
}
```

### 你面试可以这样介绍

# 修改后的前端面试版 LangChain 学习路径

## 1. 什么是 LangChain

这一章不变。

你要学：

```txt
LangChain 是什么
```

```txt
能知道 LangGraph 更底层，LangSmith 用于调试观测
```

面试回答可以这样说：

> LangChain 是一个 LLM 应用开发框架。它不是大模型本身，而是帮我们把模型调用、消息管理、工具调用、Agent 循环、流式输出、记忆和 RAG 这些常见能力组织起来。对于前端来说，理解它可以帮助我知道 AI 应用后端怎么工作，以及前端应该怎么接流式输出和结构化结果。

## 3. Agent 和 Model

这个要放到比较前面，跟你图片一致。

### 3.1 Agent 是什么

你要学：

```txt
Agent 不是模型本身
Agent 是模型 + 工具 + 控制循环
Agent 的大脑是 model
Agent 的手脚是 tools
Agent 的状态来自 messages / memory
```

你要能讲出这张图的意思：

```txt
input
  ↓
model
  ↓
如果需要行动：调用 tools
  ↓
tools 返回 observation
  ↓
observation 回到 model
  ↓
model 决定继续调用工具还是 finish
  ↓
output
```

面试回答：

> Agent 本质上是一个循环。用户输入之后，模型先判断自己能不能直接回答。如果不能，它会生成工具调用请求，程序执行工具后把结果返回给模型，模型再基于工具结果继续推理，直到最后输出答案。

### 3.2 Model 是什么

你要学：

```txt
model 是真正负责生成内容的大模型接口
LangChain 把 OpenAI、Gemini、Claude、Ollama 等封装成统一接口
常见方法：invoke、stream、batch
常见参数：temperature、maxTokens、modelName
```

学到这个程度就够：

```txt
能说清楚 Agent 和 Model 的区别
能写一个最小 model.invoke
知道模型只是“生成和决策”，真正执行动作的是程序
```

---

## 4. Messages

这个也应该跟图片一样放在 Agent 和 Model 后面，因为 Agent 和 Model 之间的通信就是 messages。

你要学：

```txt
messages 是模型上下文的最小单位
messages 不是普通字符串数组，而是有角色和内容的消息对象
```

重点掌握四类：

```txt
SystemMessage：系统指令，告诉模型要扮演什么角色、遵守什么规则
HumanMessage：用户输入
AIMessage：模型回答，可能包含 tool call
ToolMessage：工具执行结果
```

你要理解这件事：

```txt
LLM 不会自动记住上文
所谓多轮对话，就是每次请求时把历史 messages 一起传给模型
```

面试回答：

> Messages 是 LangChain 和模型之间的通用语言。每条 message 都有 role 和 content。比如 system message 约束模型行为，human message 表示用户输入，AI message 表示模型输出，tool message 表示工具返回结果。多轮对话其实就是把历史 messages 继续带给模型。

学到这个程度就够：

```txt
能写 messages 数组
知道 invoke 返回 AIMessage
知道 stream 返回的是 AIMessageChunk
知道 ToolMessage 是工具调用后回传给模型的结果
```

---

## 5. Streaming：前端重点提前学

你图片里第 5 章是“通过流式输出获取更好的体验”，这个对你非常重要，应该优先学。

你要学：

```txt
invoke 和 stream 的区别
为什么 AI 产品要流式输出
普通模型流式输出
Agent 运行过程流式输出
前端如何展示 token / chunk
```

面试回答：

> AI 应用里模型响应通常比较慢，如果等完整结果生成完再展示，用户体验会很差。所以前端一般会接 streaming，把模型生成的 chunk 一段段展示出来。对于 Agent，还可以展示工具调用状态，比如正在搜索、正在计算、正在生成最终答案。

你要能做：

```txt
用户输入问题
前端显示 loading
后端流式返回文本
前端逐字追加到页面
完成后关闭 loading
```

学到这个程度就够：

```txt
知道 stream 返回的是 chunk
前端能做打字机效果
知道 SSE / WebSocket / ReadableStream 都可以承载流式数据
```

## 6. Tools：Agent 的手脚

虽然图片把 Tools 放在 Streaming 后面，但这不影响理解。学完 Agent 和 Messages 后再学 Tools，会更顺。

## 11. RAG

RAG 可以放在 MCP 后面，也和图片差不多。

你要学：

```txt

检索
```
